# EXP-008：FOCAL-VLA 迁移到 RoboCasa365

目标是用子任务相关的几何蒸馏、未来运动蒸馏和语义辅助监督训练 π0.5。完整运行说明：[8 卡全量训练](../../docs/FOCALVLA_8GPU_TRAINING.zh-CN.md)。用户确认的本轮配置为 **8 卡、global64、70k，每10k保存**；本次交付准备训练代码，未启动正式70k。

## 方法与配方

依据用户提供的 [FOCAL-VLA 论文](https://arxiv.org/abs/2609.21228) §III、§IV-A。代码保留当前观测输入、8+8 query、冻结 VGGT/Track4World 的完整帧教师输入与实体区域池化、原生语义 CE、动作对 query 的条件读取。推理无未来帧和GT子任务输入。

标注采用此前验证的人工粗模板＋离线物理事件增强，解决小物体和遮挡的识别问题；这改变了论文的默认 Qwen3-VL-8B 标注工具，监督信息类型和模型训练路径不变。此处是论文方法的 RoboCasa365 迁移，不把 70k/global64、增强标注或采样细节写成作者原配方。

入口：[科学配置](../../configs/focalvla_robocasa365_8gpu_70k.json)、[资源模板](../../configs/focalvla_resources.example.json)、[torchrun 启动脚本](../../scripts/focalvla/train_8gpu.sh)、[完整实现](../../runtimes/focalvla/focalvla/)。

## 2026-11-15：portable 整理

复用已验证的前向与 FlashAttention 核心，去除服务器绝对路径及两卡/50步/旧checkpoint绑定。新增全量确定性采样、episode缓存、有界读取、可配置DDP、完整断点恢复。资源JSON只绑定路径；源码与实验输出分开。

本次 portable 已在单 H100 上用真实演示依次跑通：采样计划 → 离线标注 → 两个冻结教师 → 缓存封存 → DDP 训练第1步 → 完整保存 → 新进程冷恢复 → 第2步 → 完整保存。测试使用1条演示、4个缓存时刻、global2；四项损失和梯度范数有限，峰值已分配显存57.90 GiB。训练用的12张缓存RGB与源视频逐像素一致，轨迹末端重复最后一帧的测试通过。CPU的8-rank数据分片、70k学习率端点、不完整/不兼容checkpoint处理、精确AdamW/RNG续训4项测试通过。完整取样计划确实覆盖全部30,000条演示。

这次测试验证了整理后的执行链路与冷恢复，不能替代实体8卡吞吐或70k效果验收。详情见 [机器可读验收记录](validation_20261115.json)。

## 2026-11-15：取消全量RGB副本，改为训练时预取

新准备流程只落盘数值目标/状态/动作/标注，不再生成`images.bin`或PNG。训练直接从原MP4读取当前三视角，DataLoader每卡4 workers、每worker预取4个batch（初始2批设置在后续GPU对照后调整为4）。读取器按视频/帧分组并还原采样顺序，复用有界解码器，RGB缓存限制为64 MiB/worker。worker启动仅传递路径和小配置，重新打开mmap并延迟加载精简元数据，避免复制407万条索引到每个进程。

验证：6项协议/视频回归测试通过，覆盖B帧/GOP定位、乱序与重复取帧、句柄/内存上限、无PNG缓存读取、末动作补齐及worker序列化。真实视频输出与已有PNG逐像素一致；真实场景回放的缓存写出测试没有RGB文件，8类数值数组与原缓存相同（该写出测试复用已验证的教师目标，不重复运行教师）。

在22 CPU核配额的单主机上，用正式读取器和全量计划中的真实随机样本测得：4 workers为24.17 samples/s（96×B8）；32 workers为103.15 samples/s（256×B8）。这是视频解码/拼批供给量，实体8卡训练吞吐未在本次重测。新增各rank最大数据等待日志用于训练时确认。详见[视频读取验收](video_reader_validation_20261115.json)及[训练说明](../../docs/FOCALVLA_8GPU_TRAINING.zh-CN.md)。

## 2026-11-15：完整训练PNG/视频A/B与预取调整

单H100、B8、4 workers；224条真实样本覆盖158任务，672张图像逐像素一致。两种方式均执行原生预处理、H2D、完整FOCAL前向/反向、梯度裁剪和fused AdamW，每组28步、前4步预热。每组从相同模型和空Adam状态开始，逐步样本/RNG一致，组内不重复样本。A/B的PNG参考只保存这224条小样本约40.5MB，不是全量RGB缓存。

| 设置 | PNG平均秒/步 | 视频平均秒/步 | 视频减速 | 视频平均/最大数据等待 |
|---|---:|---:|---:|---:|
| 初始prefetch=2，PNG→视频 | 0.62016 | 0.85302 | 37.55% | 234.3 / 5618.9 ms |
| 发布prefetch=4，视频→PNG | 0.63157 | 0.64320 | **1.84%** | **0.224 / 0.420 ms** |

初始配置存在一次长等待，不能只引用中位数声称无减速。加深有限预取后，本次反向顺序复测没有再出现长等待；中位数差1.29%，两组逐步各项损失最大差为0。保留这两轮原始时间序列，见[机器可读GPU对照](video_training_ab_20261115.json)。正式8卡/global64/70k配方采用每worker预取4批；实体8卡训练尚未启动。

## 2026-11-15：教师离线提取提速

新增`prepare_fast.py`，标注、原视频解码/OSMesa mask与GPU教师计算并行；每卡教师常驻，以8个目标合批，只保留最终特征依赖的分支。跳过未使用的深度/相机预测、metric模型、几何后处理和2D flow，缓存有界RoPE，并避免反复转换线性层权重。参考视角选择保持逐clip原始计算，避免小矩阵合批舍入改变离散argmin。保留全部三相机、11帧运动窗口、518/630分辨率、原注意力与精度，不生成PNG/images.bin。

12类任务36个时刻与原教师对照通过；另用两条完整演示的235个计划目标执行读视频→渲染→教师→数值落盘。两类特征最大相对L2误差均低于1.83e-7，状态/动作/帧/子任务/有效标记完全相同，缓存contract一致。恢复会跳过完整集，原有完整缓存可复用。单H100整条管线实测2.03目标/秒，约0.492秒/目标；这是单卡测试，不冒充四卡实测。详见[验收数据](teacher_cache_validation_20261115.json)及更新后的[启动命令](../../docs/FOCALVLA_8GPU_TRAINING.zh-CN.md)。
